# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project intent

Build a **containerized development environment** designed to run remotely (e.g., Hetzner VPS) as an always-on container that the user attaches to and detaches from over SSH. Inside, multiple AI coding agents (Claude Code, Codex, pi-coding-agent) and editors (nvim) run under tmux. Multiple such containers may run in parallel, each holding working copies of one or more git repositories.

## Hard constraints

These are load-bearing design decisions, not preferences:

1. **No reliance on container persistence.** Every agent must `commit` AND `push` every change. The container is treated as ephemeral; if it dies, no work is lost. Any feature or workflow that depends on uncommitted state is wrong by construction.
2. **Editor-agnostic, not VSCode-locked.** The user explicitly rejected devcontainers because tooling support outside VSCode is nonexistent. Do not introduce `.devcontainer/` configs or any design that assumes a VSCode client. SSH + tmux is the canonical attach path.
3. **Multiple parallel containers.** Naming, port allocation, volume mounts, and git identity must all support N containers running simultaneously on the same host without collision.
4. **Push auth must work non-interactively.** Agents commit autonomously, so SSH keys / git credentials inside the container must be configured to push without prompts. Never embed long-lived secrets in the image — inject at runtime.

## Decisions

- **Runtime + base image:** Podman + `debian:12-slim`. See [`docs/decisions/0001-runtime-and-base-image.md`](docs/decisions/0001-runtime-and-base-image.md).
- **Rootless container, no runtime apt:** the image has NO `sudo`/root at runtime — `sshd` runs as the `dev` user on unprivileged port **2222** (host port maps `<hostport>:2222`), host key + `authorized_keys` on the dev-owned `~/.ssh` volume. Consequently **all system deps are baked at build time; agents never `apt install` at runtime** — add packages to the `Dockerfile` apt layer, never via runtime install.
- **SSH identity persists + is injectable:** the `-ssh` per-container volume (`~/.ssh`) keeps a stable host key + `authorized_keys` across recreation. Inject three ways (all land there): env-file (`SSH_AUTHORIZED_KEYS`, `SSH_HOST_ED25519_KEY_B64`), `up --host-key/--authorized-key`, or `keys <name>` (live, no recreate). Seven per-container volumes total: `workspace, claude, codex, pi, shellenv, tmux, ssh`.
- **CLI:** a single tool, `agent-container` (`bin/agent-container`) — a PEP 723 uv script (Typer + questionary + rich) covering the whole lifecycle (build/`host add`/`host ls`/`host show`/`host rm`/up/attach/logs/down/purge) plus an interactive wizard. **Multi-host (specs/001):** a *host* is a named runtime target (docker context / podman connection) in the registry `~/.config/agent-container/hosts.json` (supersedes `hosts.conf`, still read for legacy attach); `up`/`down` take `--host` (default: the registry default, else an implicit local host). **Server↔container lifecycles are separate:** `host rm` removes only the registration; `host rm --destroy` also deprovisions but is **fail-closed** — refused unless the host is tool-created AND a *provably-successful* container listing shows it empty (an unreachable daemon refuses, never reads as empty), and the registry entry is kept if the server delete fails (no orphaned billable server). **Run mechanism is compose** (needs Compose v2): `up` generates `$XDG_STATE_HOME/agent-container/<host>/<name>.compose.yaml` and runs it on the host (builds there, no registry); injected SSH identity rides as compose secrets/configs (works over a remote context). On-disk contract — container name `agent-container-<name>`, `2200 + name-hash` port, **per-host** `<host>/<name>.port` state, deterministic volume names — is single-sourced here; the shell completions read the same per-host state files. Runtime default is platform-aware (docker-first on macOS, podman-first on Linux); override with `AGENT_CONTAINER_RUNTIME`.
- **Lifecycle verbs (specs/002):** net-new on 001's `up`/`down`/`logs` — `stop`/`start` (pause/reclaim: keep container+volumes), `redeploy` (rebuild image on host + recreate, volumes preserved; **deliberately non-idempotent** — the idempotent no-op stays `up`), `wipe` (container + volumes + locally-built image, behind the `-y`/TTY confirm idiom). Every mutating verb takes a per-`(host,name)` **fcntl advisory lock** (`<host>/<name>.lock`, non-blocking → fail-fast on contention); read-only `list`/`logs` never lock. `list` is now **live-reconciled**: it queries each registered host's daemon and reconciles against the `*.port` state files (truthful after reboot/out-of-band change) — a failed enumeration is **fail-closed** (never read as "zero containers"; the host renders `unreachable`, never hangs, never dropped), `--local` skips the remote round-trips. **Sidecars:** an operator override file (`./agent-container.<name>.services.yaml` → `~/.config/agent-container/<name>.services.yaml`) is merged as a second `-f` on every compose call so agent+helpers share one project/lifecycle; validated `services:`-only, must not redefine the `agent` service. Thin file-based seam for the future agent-as-code (specs/006).
- **Agent credentialing (specs/003):** runtime-injected, **least-exposure**. A **tool-injected secret** rides as a compose `config` landing under `/run/agent-container/…` and is **never** copied to a volume (**FR-012**) — it vanishes with the container (operator's local copy is the sole durable copy), never on argv, never baked; any referenced-but-missing file `die`s **before** compose (no half-credentialed agent). **Outbound SSH push key** (`up --push-key`/`--known-hosts`, or env `SSH_PUSH_KEY_B64`/`PUSH_KNOWN_HOSTS`) → entrypoint wires `git core.sshCommand` with `IdentitiesOnly=yes` + seeded `known_hosts`; **distinct** from the inbound sshd host key (**SC-008**), never on the `~/.ssh` volume; HTTPS+`GH_TOKEN` retained as the layered alternative (per-repo deploy key = a narrower `--push-key`). **File-first API keys** (rule **H1**): convention `./agent-container.<name>.<provider>.key` → `INJECT_APIKEY_DIR` ephemeral — Claude via an `apiKeyHelper` in the fresh `settings.json`, Codex/pi via an ephemeral `$HOME` redirect (`CODEX_HOME`/`PI_CODING_AGENT_DIR`) so `auth.json` never lands on the agent volume; on-volume `auth.json` = **operator-interactive login only**; env/`.env` keys retained. **Canonical config** `./agent-container.<name>.config/…` → `INJECT_CONFIG_DIR`, copied fresh onto the agent volume each boot (edits propagate on `redeploy`) while runtime state persists; a secret-bearing config file is classified **secret** (ephemeral). Rotate = local edit + `redeploy`. Docs: [`docs/credentials.md`](docs/credentials.md).
- **Agent execution (specs/004):** `up`/`redeploy` own what runs inside + how you drive it. **`--mode interactive|headless`** (default interactive): the entrypoint branches on `AGENT_CONTAINER_MODE` — interactive = today's sshd+tmux plus the agent launched in a dedicated window (`restart: unless-stopped`); headless = the agent's non-interactive form as PID 1, the **container exits with the agent's code** (`restart: on-failure` — a success is not resurrected, a failure follows policy). `build_compose_model` gained a **`restart` param** (no longer hardcoded). **`--agent claude|codex|pi`** (default claude) + **`--task <text|@file>`** delivered as an ephemeral injected file (003 channel; never argv/env). Headless **`--foreground`** runs `compose up` attached with `--abort-on-container-exit --exit-code-from agent` (CLI exit = agent exit; headless-only, refused otherwise). **`--workspace persistent|bind|ephemeral`** (default persistent) = what mounts at `/workspace`: named volume (survives) / local dir (`--workspace-dir`, **local hosts only**, remote refused) / nothing (container layer, **gone on teardown** — a deploy-time NOTE warns). The **workspace named volume is conditional** (persistent only; the other six + name/port unchanged, `--purge`/`wipe` tolerate its absence — no migration). **Clone-on-start `--repo`** (persistent/ephemeral): credential by URL scheme — `git@…`/`ssh://…` → injected push key (**SSH URL + no key = fail fast**), `https://…` → `GH_TOKEN`; idempotent (skip if `/workspace` populated). Clone URL rides `AGENT_CONTAINER_CLONE_URL` — **distinct** from `AGENT_CONTAINER_REPO` (the CLI's host-side build-context override). `attach` now **probes `tmux has-session` first** → a dead session is reported ("nothing running"), never a silent empty shell. Mode × workspace independent. Docs: [`docs/execution.md`](docs/execution.md).
- **Packaging + release:** ships to PyPI as the `agent_container` module via a hatchling `force-include` wheel (`bin/agent-container` → `agent_container/__init__.py`; completions → `agent_container/completions/*` package data). `REPO_ROOT` resolves location-independently (`AGENT_CONTAINER_REPO` → `Dockerfile`+`completions/` marker → `None`) so a **non-editable** PyPI install works standalone (`up/down/list/attach/logs/purge/completions`); only `build` needs a checkout (via `AGENT_CONTAINER_REPO`/`--context`). `uv tool install --editable .` remains the dev path. Licensed **MIT** ([`LICENSE`](LICENSE)).
- **CI/CD — Continuous Deployment:** `ci.yml` runs parallel jobs on every push/PR (`quality-gate` = `scripts/quality-gate.sh` (ruff · ty · bandit · vulture · xenon · refurb · self-test · pytest · shell suites) · `test` = pytest on the pinned 3.14 interpreter · `commits` = Conventional-Commits check (PRs) · `build` = `uv build` · `acceptance` = real-container validation). The tool targets **Python ≥ 3.14** (`requires-python`, ruff `target-version = py314`); the CLI is a host tool, so this is the operator-machine floor, not the container's baked Python. On a **merge to `main`, once `ci` passes** (`publish.yml` fires via `workflow_run`), **python-semantic-release** computes the strict-semver bump from Conventional Commits (`feat`→minor, `fix`→patch, breaking→minor while pre-1.0; docs/ci/chore/test/style cut **no** release), bumps `pyproject.toml [project].version` + `CHANGELOG.md`, commits `chore(release): X.Y.Z [skip ci]`, tags `vX.Y.Z`, and publishes to PyPI via **OIDC Trusted Publishing** (no stored token). Version is single-sourced in `pyproject.toml`; the CLI reports it via `--version`. So **every substantive merge to main is a release** — no manual tagging, no release PR. (Prereq: the PyPI project's Trusted Publisher must point at workflow `publish.yml` + the `release` environment — the workflow file is kept named `publish.yml` to match that binding.)

## Architecture (keep these layers separate)

- **Container image** (`Dockerfile`) — base OS + tmux + sshd + nvim + git + the agent CLIs and their runtimes.
- **Orchestration** (`bin/agent-container` + compose/quadlet) — launch, name, attach, tear down.
- **Entrypoint** (`entrypoint.sh`) — git identity, credential injection, sshd + default tmux session.
- **Attach** — thin client-side `ssh … -t tmux attach` helper across hosts/containers.

Don't bake host-specific orchestration into the image.

## Conventions for future work

- The container is **rootless by decision** (see Decisions): no `sudo`/root at runtime, sshd as `dev` on port 2222. Keep it that way — don't reintroduce root-only steps; bake deps at build. Also avoid features that only work on Docker Desktop (stay Podman-compatible).
- Treat the **commit-and-push discipline** as a property of the agent configuration, not something to enforce via git hooks alone (hooks can be bypassed; the agents themselves should be configured to push).
- **Quality gate — one script, two uses.** `scripts/quality-gate.sh` is the single source of truth for the fast checks (ruff check + format, **ty** type check, **bandit** security scan (`-ll`, MEDIUM+ only — the CLI's legitimate subprocess calls are all LOW), **vulture** dead-code, **xenon** complexity (rank B / CC≤10), **refurb** modernizations (`[tool.refurb]` ignores FURB143 — a false positive on Typer `None`-default list options), `--self-test`, hermetic pytest, shell suites). The **ty** step self-heals a corrupted volatile-`$TMPDIR` cache venv: it detects the phantom third-party `unresolved-import` signature against the real target and rebuilds+retries once (never a spurious gate failure). The local Claude Code **Stop hook** runs it and feeds failures back for auto-fix (`exit 2`); the **CI `quality-gate` job** runs the *same* script as a hard gate. Register the hook per-clone (`.claude/` is gitignored) — see the header of `scripts/quality-gate.sh`. The gate excludes the slow **acceptance** layer (real containers): that is the authoritative CI-only tier (`pytest -m acceptance bin/tests`; on macOS+Lima its work dir must be Lima-shared — defaults to `~/.cache/agent-container-acceptance`, override `AGENT_CONTAINER_ACCEPTANCE_TMPDIR`). `ci.yml` also runs the pinned-interpreter pytest job, `commits`, `build`, and `acceptance`; a gate failure blocks the release (Principle VII).
- **Conventional Commits are mandatory** — the CD pipeline (Principle VII) reads them to compute releases. Enforced three ways: (1) a local `commit-msg` hook (`.githooks/`, via `git config core.hooksPath .githooks` — run once per clone) that runs `commitizen` (`cz check`); (2) the `commits` CI job validating a PR's commits; (3) a GitHub **ruleset** rejecting non-conforming commits on push to `main` (`.github/conventional-commits-ruleset.json`; apply with `gh api -X POST /repos/ondrasek/agent-container/rulesets --input .github/conventional-commits-ruleset.json`). Types: `feat`/`fix`/`docs`/`style`/`refactor`/`perf`/`test`/`build`/`ci`/`chore`/`revert` (+ `!`/`BREAKING CHANGE` for breaking). Merge/revert messages pass. `--no-verify` bypasses the local hook only.
- When proposing a tool or dependency, justify it against the constraints above — especially the "not VSCode-locked" one.

## Out of scope (don't add unless asked)

- IDE integrations beyond plain SSH/tmux/nvim.
- Multi-user / multi-tenant access controls — single operator (the user) is assumed.
- Kubernetes manifests — the target is a single VPS running a container runtime, not a cluster.
